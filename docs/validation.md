## 再現手順

開発環境の準備はREADMEを参照。

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/make_test_videos.py --benchmark
```

ブラウザー検証用サーバーを起動する。ready-fileは未使用のパスを指定する。
ファイルには操作用トークンが含まれるのでコミット・共有しない。

```bash
.venv/bin/sen-cha serve --no-browser \
  --ready-file /tmp/tvfc-check-ready.json
```

別端末からローカルブラウザーを操作する。

```bash
.venv/bin/python scripts/check_browser.py \
  /tmp/tvfc-check-ready.json --shutdown
```

このスクリプトは`/usr/bin/google-chrome`を使うUbuntu用の検証補助であり、
配布アプリの対応OSを制限するものではない。ブラウザー通信を127.0.0.1へ限定する。
結果のレポートと画面キャプチャは`test-results/`へ保存し、コミットしない。

## 自動検証の対象

- 静止画、単発切り替え、フェードを標準設定で候補にしない。
- 毎秒4回の明暗、部分領域、赤色の反復を検出する。
- 毎秒3回の反復は標準設定で候補にしない。
- 固定の秒境界をまたぐ4組の反復を検出する。
- 高感度で標準の検出根拠を失わない。ランダム入力でも確認。
- H.264とVP9、30fpsと60fps、可変フレームレートで時刻とフレーム数を確認。
- HDRタグ付き動画を未対応とする。
- 破損動画とネットワークURLを含むプレイリストを拒否する。
- 日本語・空白付きファイル名を扱える。
- HTMLエスケープ、CSV数式対策、固有名による非上書き保存。
- トークンなし、不正Host、不正Origin、Originなしの変更要求を拒否する。
- 処理開始前・デコード中の中止、一時領域削除、再解析。
- 小分けコピーの重複・順序違い・未完了・中止後の古い要求を拒否する。
- 空き容量不足と放置されたコピーを処理し、一時領域を削除する。

## 初回性能測定

FFmpegのtestsrc2で作成した60秒・1920×1080・30fps・H.264・約81MiBの合成動画。
初回はPyPI標準NumPy wheelを使った測定。

| 項目 | 初回測定値 |
|---|---:|
| フレーム数 | 1800 |
| 解析処理時間 | 7.11秒 |
| 動画時間÷解析時間 | 約8.43倍 |
| 解析プロセス最大RSS | 約40.4MiB |
| デコーダー等の子プロセス最大RSS | 約51.4MiB |

RSSはプロセス群の同時合計ではなく、それぞれのピーク値。
ブラウザーのメモリー、初回起動、一時コピー、結果表示の時間は含まない。
速度は動画内容・コーデック・PC・感度に依存し、この倍率を保証しない。

```bash

  tests/generated/benchmark-1080p.mp4
```

## 最終確認結果

- 自動テスト: **27 passed（9.34秒）**。配布用のBLAS/LAPACKなしNumPy構成で実行。
- 最終コードの配布アーカイブを別フォルダーへ展開し、開発用PATHなしでバージョン表示と画面起動に成功。
- その配布版に対し、上記Chrome操作試験が成功。破損入力からの復帰、中止後の再解析、終了も成功。
- JavaScript例外なし、ブラウザーからの外部リクエストなし。
- NumPyの構成と配布ファイルを照合し、OpenBLAS・libgfortran・libquadmathを同梱していないことを確認。
- FFmpegのソース・署名・ビルド手順、依存ライブラリのライセンス原文を同梱。

最終依存構成で、他のビルド処理を実行せずに同じ60秒動画を再測定した結果:

| 項目 | 最終測定値 |
|---|---:|
| フレーム数 | 1800 |
| 解析処理時間 | 6.16秒 |
| 動画時間÷解析時間 | 約9.75倍 |
| 解析プロセス最大RSS | 約41.1MiB |
| デコーダー等の子プロセス最大RSS | 約53.5MiB |

この測定は同じ解析エンジンを開発環境のCLIから実行した値で、GUI操作全体の所要時間ではない。

## 専用ウィンドウ・YouTube URL拡張の確認

追加Goalの範囲は`GOAL-desktop-youtube.md`。初期版の検証値を上書きせず追記する。

- YouTube URLの受け付けは`youtube.com`・`youtu.be`の単一動画IDに限定。偽ホスト、ユーザー情報付きURL、HTTP、別ポート、プレイリスト、重複ID、ローカルファイルURLを拒否する自動試験を追加。
- yt-dlpを模擬した取得試験で、外部設定・プラグイン・ブラウザーCookieを使わず、進捗、取得後の動画ファイル、取得中止を確認。
- Chromeによる実画面試験で、不正なURLを外部へ送信せずに拒否し、従来のファイル解析、3形式の保存、破損入力からの復帰、中止、再解析を確認。
- UbuntuのGTK/WebKitGTKで動画ファイルの選択、解析、候補表示、専用の保存ダイアログからHTMLレポート保存、アプリ終了まで確認。ブラウザーのダウンロード方式はWebKitでは発火しなかったため、専用ウィンドウにはネイティブ保存処理を追加した。
- QuickJS 2026-06-04の公式ソースから`qjs`をビルドし、yt-dlpから対応ランタイムとして認識されることを確認。
- 追加実装後の自動試験は46件成功。容量上限とURL偽装、専用ウィンドウの起動に関するケースを含む。
- 配布アーカイブを別フォルダーへ展開し、開発用PATHなしで版表示、専用ウィンドウ起動、Chromeによる一連の操作を確認した。
- 最終配布フォルダー内272ファイルのSHA256を照合。QuickJS、EJS、ソース、Astring/Meriyahを含むライセンス表示を確認。配布版内のGTK起動ファイルで動画選択、解析、HTML保存、終了も通過。
- ウィンドウを外部から強制的に閉じた場合も親アプリは終了する。GTKが非ゼロ終了した際は起動失敗と誤表示しないよう修正した。
